# 실무형 인과추론 플레이북

> 목표: 관측자료 기반 실무 분석에서 **(i) 인과 질문을 명확히 정의**하고, **(ii) 식별 가정을 문서화**하며, **(iii) 설계→추정→진단→보고**를 표준화한다.  
> 원칙: “모형을 잘 맞추는 것”이 아니라 **식별(identification)** 을 먼저 해결한다.

## 0. 이 문서의 범위와 사용 규칙

### 0.1 적용 범위
- A/B 실험(무작위배정)과 관측자료(비무작위) 모두 포함하되, 본 문서는 **관측자료에서의 인과추론**을 중심으로 한다.
- 결과물은 “증명”이 아니라 **가정 하에서의 정량적 근거**로 제시한다.

### 0.2 절대 규칙 (Fail-fast)
아래 중 하나라도 만족하지 못하면, 분석 착수를 보류하고 설계를 재검토한다.
- [ ] 처치(T), 결과(Y), 시간(t), 분석단위(unit)가 **운영 정의**로 고정됨
- [ ] **반사실(counterfactual)** 이 문장으로 표현됨
- [ ] 최소 하나의 **식별 전략**(backdoor/IV/DiD/RDD/SCM 등)이 명시됨
- [ ] “필수 가정”과 “검증 가능한 진단”이 분리되어 문서화됨

## 1. STEP 1 — 인과 질문 정식화 (Causal Question & Estimand)

### 1.1 용어를 잠재결과로 고정
- 잠재결과: $Y_i(1)$ = i가 처치를 받았을 때 결과, $Y_i(0)$ = 처치를 받지 않았을 때 결과  
- 관측결과: $Y_i = T_i Y_i(1) + (1-T_i)Y_i(0)$

### 1.2 필수 정의(운영 정의)
- **Treatment (T)**: 무엇을 “처치”로 볼 것인가? (예: 광고비 증액 여부, 정책 시행 여부, 기능 노출 여부)
  - 강도/연속 처치라면: 단위 증가(Δ)와 범위, 비선형 가능성까지 정의
- **Outcome (Y)**: 측정 방식, 집계 방식(일/주/월), 로그변환 여부, 윈저라이징 등 전처리 규칙
- **Unit**: 개인/계정/매장/지역/상품 등
- **Time**: 처치 시점과 관측 윈도우(사전/사후 기간), 지연효과(lag) 고려
- **Interference**: 단위 간 간섭 가능성(네트워크, 경쟁 매장, 바이럴 등) 여부

### 1.3 Estimand 명시(해석의 단위)
- **ATE**: $E[Y(1)-Y(0)]$
- **ATT**: $E[Y(1)-Y(0)\mid T=1]$
- **CATE**: $E[Y(1)-Y(0)\mid X=x]$
- **ITT / TOT**(정책/실험에서): 준수(compliance) 이슈가 있으면 별도 정의

> 체크: “어떤 집단에 대한 어떤 평균 효과인가?”가 문장으로 고정되어야 한다.

### 1.4 SUTVA/일관성(Consistency) 및 처치 정의의 엄밀성
- 같은 T라도 “노출 강도”가 다르면 사실상 다른 처치가 될 수 있다.  
- **처치 버전(version) 문제**를 피하기 위해 최소한 다음을 문서화:
  - 노출 규칙(누가, 언제, 어떤 조건에서, 얼마나)
  - 대체 처치(contrast) 정의: “증액하지 않음”이 무엇을 의미하는가?

## 2. STEP 2 — 데이터·설계 진단 (Design Triage)

### 2.1 데이터 구조 체크리스트
- [ ] 실험 / 준실험 / 순수 관측
- [ ] 단면 / 패널 / 반복 단면 / 시계열
- [ ] 처치가 단일 시점인가? 단계적 도입(staggered)인가?
- [ ] 처리 할당이 개인 선택(자기선택)인가, 정책/운영 룰 기반인가?
- [ ] 결과에 계절성/추세/캘린더 효과가 있는가?

### 2.2 실무에서 흔한 위험 신호
- **선택편의**: 성과가 좋은 집단이 처치를 더 받는 구조(타기팅)
- **누락 교란(Confounding)**: 성과 잠재력이 높은 팀/지역에 리소스 집중
- **측정오차**: 로그 누락, 어트리뷰션 변경, 트래킹 버전 변경
- **결측/검열**: 이탈/휴면으로 인해 결과가 관측되지 않는 구조(MNAR 가능)
- **동시 정책/캠페인**: 처치와 함께 다른 변화가 동반됨

> 목적: “할 수 있는 것”보다 먼저 **‘무엇을 식별할 수 없는지’** 를 찾는다.

## 3. STEP 3 — 식별 전략 선택 (Identification)

> 핵심: **식별 가정**을 최소화하면서 데이터 구조와 운영 맥락에 맞는 전략을 선택한다.

### 3.1 먼저 DAG(인과 그래프)로 가정을 고정
- [ ] 최소 변수: T, Y, 핵심 교란 후보 X, 시간/정책/운영 룰
- [ ] 금지: post-treatment 변수(처치 이후에 결정되는 변수)를 “교란”로 착각해 통제
- [ ] collider(공통 결과 변수) 통제로 인한 편향 가능성 점검

### 3.2 결정 트리(실무형)
1) **무작위 배정/준무작위가 가능한가?**
- Yes → 실험/준실험(최우선), ITT/TOT 명확화  
- No → 2로

2) **Backdoor(조건부 교환가능성) 가정이 현실적인가?**  
- 질문: “T와 Y의 공통 원인을 충분히 관측했는가?”
- Yes → 매칭/가중치/회귀/이중강건(DR)  
- No → 3로

3) **외생적 변동(도구변수 IV)이 존재하는가?**
- 조건: 관련성 + 배제제한 + (가능하면) 단조성  
- Yes → IV(LATE 해석)  
- No → 4로

4) **전후 비교 + 대조군(혹은 반복 관측) 구조가 있는가?**
- 평행추세(Parallel trends) 가정이 설득 가능한가?
- Yes → DiD / 이벤트 스터디  
- No → 5로

5) **경계/컷오프 기반의 할당 규칙이 있는가?**
- Yes → RDD(연속성 가정, 조작 테스트)  
- No → SCM/구조 모형/부분식별(바운딩) 또는 “인과 결론 보류”

> ❗ “회귀분석”은 식별 전략이 아니다. 회귀는 **식별 전략을 구현하는 추정 도구**다.

### 3.3 공통 식별 가정(반드시 문서화)
- **Exchangeability(교환가능성)**: $Y(0),Y(1) \perp T \mid X$
- **Positivity(겹침/중첩)**: 모든 X에서 $0 < P(T=1\mid X) < 1$
- **Consistency(일관성)**: 관측된 처치가 잠재결과 정의와 동일
- **No interference(간섭 없음)**: 단위 간 처치가 결과에 영향 미치지 않음(필요 시 완화 모델링)

## 4. STEP 4 — 추정 (Estimation) 및 추론 (Inference)

### 4.1 “설계 고정 → 추정” 원칙
- [ ] 공변량 선택, 표본 제한, 윈도우 정의를 **추정 전** 확정
- [ ] 가능하면 분석 계획(간단한 pre-analysis note)로 남김
- [ ] 다중 시도(p-hacking) 방지: 주 분석 1개 + 보조 분석(명확히 구분)

### 4.2 방법별 권장 추정과 필수 산출물

#### A) Backdoor (Matching / Weighting / Regression / DR)
- 권장 추정:
  - 성향점수(PS) 기반 **가중치(IPW)** + 안정화(스태빌라이즈)
  - **이중강건(DR/AIPW, TMLE 계열)**: PS 모형과 결과 모형 중 하나가 맞아도 일관 추정
- 필수 산출물:
  - [ ] PS 분포 및 overlap 시각화
  - [ ] 가중치 분포(극단치 여부), trimming 규칙
  - [ ] 공변량 균형(SMD 등) 전/후 표
- 주의:
  - post-treatment 변수 포함 금지
  - “많이 넣으면 안전”이 아님(콜라이더/과조정 위험)

#### B) IV (Instrumental Variables)
- 식별 가정(명시 문구로 포함):
  - 관련성: $Cov(Z,T)\neq 0$
  - 배제 제한: Z는 T를 통해서만 Y에 영향
  - 독립성: Z ⟂ 잠재결과/교란 (조건부일 수도)
  - 단조성(필요 시): defier 없음
- 필수 산출물:
  - [ ] 1단계 강도(F-stat 등) 및 약한 도구 민감성
  - [ ] LATE 해석 범위(“complier”에 한정) 명확화
- 주의:
  - LATE를 ATE처럼 일반화 금지

#### C) DiD / Event Study
- 필수 가정: 평행추세(정책이 없었으면 두 집단의 추세가 같았을 것)
- 필수 산출물:
  - [ ] 사전 추세(pre-trend) 이벤트 스터디 그래프
  - [ ] 처리 시점 내생성(정책이 성과 악화 때문에 시행?) 가능성 논의
  - [ ] 이질적 처리시점(staggered adoption) 시 적절한 추정기 선택 및 해석(단순 TWFE 주의)
- 주의:
  - 동시 정책/캠페인 통제의 한계 명시

#### D) RDD (해당 시)
- 필수 산출물:
  - [ ] 컷오프 주변 밀도(조작) 점검
  - [ ] 대역폭 민감도, 함수형 선택 민감도

### 4.3 표준오차/추론(실무 최소 기준)
- [ ] 패널/군집 구조 시 **클러스터 표준오차**(지역/매장/계정 등) 고려
- [ ] 시계열/정책 분석은 자기상관 가능성 점검
- [ ] 효과 크기와 불확실성(신뢰구간)을 함께 보고

## 5. STEP 5 — 진단 및 민감도 분석 (Diagnostics & Sensitivity)

### 5.1 “검증 가능한 것”과 “검증 불가능한 것”을 분리
- 검증 가능한 진단:
  - [ ] overlap/공변량 균형
  - [ ] placebo(가짜 처치 시점/가짜 결과)
  - [ ] pre-trend / falsification outcome
  - [ ] 결과 정의 변경(견고성), 윈도우 변경(견고성)
- 검증 불가능(하지만 논의/민감도 필요):
  - 미측정 교란
  - 배제 제한(IV)
  - 평행추세(완전 검증 불가)

### 5.2 미측정 교란 민감도(권장)
- “얼마나 큰 미측정 교란이면 결과가 뒤집히는가?”를 정성/정량으로 요약
- 보고서 본문에 최소 3줄 요약:
  - (i) 어떤 교란이 가능하고  
  - (ii) 어느 방향으로 편향을 만들며  
  - (iii) 결론의 강건성이 어느 정도인지

## 6. STEP 6 — 해석 및 의사결정 연결 (Interpretation → Decision)

### 6.1 결과 보고 템플릿(필수 포함)
> 본 분석은 **[식별 전략]** 을 사용하여 **[estimand]** 를 추정했다.  
> 핵심 식별 가정은 **[가정 1, 2, 3]** 이며, 점검한 진단은 **[진단 요약]** 이다.  
> 추정된 효과는 **[효과크기] (95% CI: [.., ..])** 로, **[업무 KPI 단위]** 로 환산하면 **[해석]** 이다.  
> 다만 **[주요 한계/위협]** 에 의해 해석이 달라질 수 있으며, 따라서 본 결과는 **[의사결정에서의 사용 범위]** 로 제한한다.

### 6.2 금지 표현(강한 인과 주장 금지)
- “인과관계가 입증되었다”
- “정책 효과가 확실하다”
- “교란은 모두 통제되었다”

### 6.3 권장 표현(조건부 인과)
- “○○ 가정 하에서 추정된 평균 인과 효과”
- “대안 설명(미측정 교란/동시 정책)이 충분히 작다는 전제 하에”
- “의사결정에 참고 가능한 정량 근거(불확실성 포함)”

## 7. 실무 실패 유형(재발 방지 체크)

- [ ] DAG는 그렸으나 post-treatment/collider 통제 실수
- [ ] DiD에서 사전 추세 확인 없이 결과만 제시
- [ ] IV의 LATE를 전체 평균 효과로 과대 일반화
- [ ] overlap 붕괴(가중치 폭발)인데도 그대로 추정
- [ ] 결과 크기만 강조하고 가정·진단은 부록으로 밀어냄
- [ ] 데이터 생성/측정 체계 변경(트래킹/정의 변경)을 무시

## 8. 프로젝트 시작용 1페이지 체크리스트(복사해서 사용)

### 8.1 질문/정의
- [ ] T, Y, Unit, Time, Counterfactual 문장으로 작성
- [ ] Estimand(ATE/ATT/CATE/ITT/LATE) 명시
- [ ] 간섭/스필오버 가능성 평가

### 8.2 식별/설계
- [ ] DAG 작성 및 backdoor/IV/DiD/RDD 중 선택
- [ ] 핵심 가정 3개를 “검증 가능/불가능”으로 구분

### 8.3 추정/진단
- [ ] 주 분석(1개) + 보조 분석(견고성) 분리
- [ ] 균형/overlap, placebo, pre-trend 포함
- [ ] 표준오차(클러스터/자기상관) 처리

### 8.4 보고
- [ ] 효과크기 + 신뢰구간 + KPI 환산
- [ ] 한계/위협/적용 범위 명시
- [ ] 의사결정 권고는 “조건”과 함께 제시
