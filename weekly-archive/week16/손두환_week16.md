# 들어가기 전, 짚고갈 것: 실험 패러다임의 분기
## RCT · Switchback · 지역실험+SCM의 관계
이 세 방법은 포함관계가 아니라 **식별 논리가 서로 다른 독립적인 실험 패러다임**이다.

* **RCT**
  * 가장 강력하지만 적용 가능한 환경이 제한적
* **Switchback**
  * 공간 랜덤화는 불가능하나, 시간 랜덤화가 가능한 경우의 최선
  * 설계 실패 시 식별 자체가 무너짐
* **지역실험 + SCM**
  * 랜덤화가 구조적으로 불가능한 세계에서의 표준적 접근
  * 설계·진단·해석의 부담이 가장 큼

| 구분             | RCT      | Switchback                   | 지역실험 + SCM    |
| -------------- | -------- | ---------------------------- | ------------- |
| 무작위화 축         | 단위(unit) | 시간(time)                     | 없음            |
| 식별의 근거         | 단위 랜덤화   | 시간 랜덤화                       | 구조적 비교        |
| counterfactual | 설계로 보장   | 설계로 보장                       | 추정으로 구성       |
| 핵심 가정          | 거의 없음    | non-anticipation, finite lag | 평행추세, 구조적 안정성 |
| 주요 리스크         | 랜덤화 붕괴   | carryover, 시간 구조 변화          | 외삽, 구조 변화     |
| 분석 난이도         | 낮음       | 중간                           | 높음            |

> **Switchback은 RCT의 대체물이 아니라,
> 무작위화를 ‘공간’이 아닌 ‘시간’으로 옮긴 실험이다.**
## 실험 초기 설계 단계에서 반드시 갈라야 하는 질문 

실무에서 가장 중요한 분기점은 다음 **두 단계 질문**이다.
### 질문 1
**“이 시스템에서 단위(unit)에 대한 무작위 처치가 구조적으로 가능한가?”**

#### YES → RCT 세계
* 사용자 단위, 요청 단위, 노출 단위
* 간섭(spillover) 무시 가능
* 실험 단위가 충분히 많음

**→ 단순한 분석, 강한 식별력, 낮은 해석 리스크**

#### NO → 질문 2로 이동
### 질문 2
**“공간 단위에서는 불가능하지만, 시간에 대한 무작위 처치는 가능한가?”**

#### YES → Switchback 세계
* 도시·시스템 전체에 동일한 정책 적용
* 시간 블록별 ON/OFF 가능
* carryover가 짧거나 모델링 가능

**→ 시간 랜덤화 기반 인과추론, 설계가 절대적으로 중요**

#### NO → 지역실험 + SCM 세계
* 도시 단위, 지역 단위
* 네트워크 효과·spillover 존재
* 정책·가격·광고처럼 부분 실험만 가능
* 시간·공간 모두에서 랜덤화 불가

**→ 설계가 핵심, 추정은 그 다음, pre-period 진단이 필수**

## 한 눈에 보는 실무용 의사결정 트리
```
실험 시작
   │
   ├─ 단위 랜덤화 가능?
   │        ├─ YES → RCT
   │        └─ NO
   │
   ├─ 시간 랜덤화 가능?
   │        ├─ YES → Switchback
   │        └─ NO
   │
   └─ 지역실험 + SCM
```

# 지역실험
: 통제집단합성법이 잘 되기위해 데이터를 어떻게 세팅해야할 지 실험설계 수준의 작업임.  
SCM이 잘 작동하려면 처치 이전에 실험군의 시계열이 대조군의 convex combination으로 잘 근사되어야 한다.   
따라서 설계 단계에서 "어떤 도시 집합이 이런 성질을 가질까?" 를 미리 고르는 것이 합리적이다.  

데이터 구조  
- **단위**: 도시 $i = 1, \dots, N$
- **시간**: $t = 1, \dots, T$ (일 단위)
- **관측값**: $Y_{it}$ (각 도시 $i$의 시점 $t$에서의 결과변수)

**실험 설계 단계에서의 제약**:
- 처치 여부는 아직 결정되지 않음
- 처치 이후(post-treatment) 데이터는 사용하지 않음
- **처치 이전(pre-treatment) 데이터만으로 설계**

**목표**  
- 전체 시장을 대표할 수 있는 소수의 도시를 실험군(treatment group)으로 선택
- 나머지 도시는 **대조군(control pool)** 으로 사용
- 실험군의 처치 효과를 이후에 신뢰성 있게 추정할 수 있도록 설계

Geo experiment의 설계는 두 가지 목표를 동시에 달성해야 한다:
1. **대표성 (Representativeness)**
  - 실험군 도시들의 집계 결과가 전체 시장(또는 목표 집단)의 평균 행동을 잘 근사해야 함
2. **비교 가능성 (Comparability)**
  - 실험군과 대조군은 처치 이전(pre-period)에 매우 유사한 시계열 패턴을 가져야 함

**이 두 목표를 처치 이전 데이터만으로 만족하도록 설계하는 것이 핵심이다.**

## 통제집단합성법을 돌리기 위한 실험 설계
통제집단합성법으로, 모든 실험 대상의 평균 행동을 근사하는 가상의 실험군(synthetic treatment unit)을 찾는다. 실험군 찾고 나머지 샘플들은 대조군.  
**적은수의 실험대상에서 최적의 실험군 선택에 유리함**  
1. (Post를 관측할 수 없긴 하지만 이상적인 모습을 그려가는 과정) 
- 지금 목표: 실험군도 찾기
- 개체마다 평균에 기여하는 정도가 다름: 가중치 벡터 (예: 도시 별 인구수 normalize해서 가중치 벡터화하기) $\bold f$로 표현 $$\bold Y_{post}\bold f \approx \bold Y_{post}\bold w$$
- $\bold f \in \mathbb{R}^N$, $f_i \geq 0$, $\sum_i f_i = 1$
  - 위 식에 $\bold w$ 찾는게 우선 목표임
  - f=w이면 모든 도시가 실험군이어서 대조군이 없게되버림: 아래 제약조건 추가함
  - $|\bold w|_0<N$: w의 0아닌 요소 갯수가 전체 N보다 작아야 한다는 제약조건
  - 이 식은 이상적인 목표로, 처치후 Y를 관측할 수 없어서 해결불가능

2. (Post를 관측할 수 없긴 하지만 이상적인 모습을 그려가는 과정2)
  - 지금 목표: 대조군도 찾기
  - 대상을 대략적으로 표현하면서, 실험군과는 달라야함: $$\bold Y_{post}\bold f \approx \bold Y_{post}\bold v\\
  \text{s.t. }\forall i ,\ w_iv_i = 0$$
  - w의 0아닌 요소: 실험군
  - v의 0아닌 요소: 대조군
  - 이 식 역시 이상적인 목표로, 처치후 Y를 관측할 수 없어서 해결 불가능. 이를 $Y_pre$로 근사하여 해결하고자 아래 방법이 제안됨.
  - 추가
    - 실험군의 규모가 지나치게 커지면 실험의 비용과 복잡도가 증가하고, 전체 시장을 대표하는 "부분 실험" 이라는 의미가 약화되므로 실험군 도시는 최대 m개까지만 선택하도록 sparsity 제약을 둔다.
    - 한편, 도시 단위 데이터에서는 도시 규모(인구, 매출 등)가 heavy-tailed 분포를 따르는 경우가 일반적이며, 소수의 대도시가 전체 시장 수준을 지배한다.
    - 이로 인해 전체 시장 평균과 실험군 또는 대조군 평균 사이에는 상수적인 레벨 차이(level difference) 가 존재하는 것이 자연스럽다.
    - 따라서 통제집단합성법 설계 단계에서는 절편(intercept)을 허용하여 이러한 구조적 규모 차이를 흡수하고, 절대 수준이 아니라 시간에 따른 변화 패턴(shape) 에 맞추도록 한다.
    - 이 관점에서 절편 이동은 **전체 시장 수준과 실험군/대조군 평균 수준 간의 상수적 차이를 허용함으로써 시계열의 공통 동학(dynamics)에 집중하기 위한 장치** 로 해석된다.

3. 추가요구사항 + 두 가지 목표 종합:  
  - **목적함수:** $$\min_{w,v} \|Y_{\text{pre}}f - Y_{\text{pre}}w_{\text{tr}} - \alpha_0\|^2 + \|Y_{\text{pre}}f - Y_{\text{pre}}v_{\text{co}} - \beta_0\|^2$$
  - **제약조건:** $$\begin{align}
  &\sum_i w_i = 1, \quad \sum_i v_i = 1 \\
  &\forall i,\ w_i \geq 0, \quad v_i \geq 0 \\
  &\forall i,\ w_i v_i = 0 \\
  &|w|_0 \leq m
  \end{align}$$
    - $Y_{\text{pre}}$: 처치 이전(pre-treatment) 구간의 결과변수 행렬
    - $f$: 전체 시장(또는 목표 집단)의 비중 벡터
    - $w$: 실험군(처치군) 도시 가중치 벡터, $w_{\text{tr}}$는 그 중 실험군에 해당하는 부분
    - $v$: 대조군 도시 가중치 벡터, $v_{\text{co}}$는 대조군에 해당하는 부분
    - $\alpha_0, \beta_0$: 절편(intercept) 상수값
    - $|w|_0$: $w$의 원소 중 0이 아닌 개수(ℓ₀-"norm", sparsity 제약)
    - $m$: 실험군 도시에 허용하는 최대 개수
    - (3): $w_i, v_i$가 동시에 1이면 안된다
- 이 목적함수는 볼록하지 않아서 최적의 답은 찾을 순 없지만, rough한 해답을 찾는데는 문제없다
  - m개씩 뽑아서 목적함수 값을 본다.
  - K trial을 시도해서 가장 최적이었던 m개 조합을 비교군, 나머지는 대조군으로 선정한다.
  - 이 과정은 오래걸리는 최적화 문제이므로, 대안으로
    - 간단한 무작위 탐색
    - 최적화 제약이 있는 2차프로그래밍 문제로 변환
    - enumerate 사용
    - genetic algorithm 사용
    - simulated annealing
    - 등 다양한 방법이 있다.

# Switchback experiment (스위치백 실험)
**참고**  
**RCT** → 가능하면 항상 최우선  
**스위치백** → 공간 랜덤화는 불가능하지만 시간 랜덤화가 가능할 때 최선  
**지역실험 + SCM** → 랜덤화가 구조적으로 불가능할 때 설계와 추정으로 해결  

**스위치백 실험 개요**
- 스위치백 실험의 추정 목표
  - 스위치백은 설계 단계에서 시간 블록에 처치 ON/OFF를 랜덤 배정하는 실험이다.
  - 최종 목표는 RCT의 ATT에 대응하는 **평균 처치효과 $\tau$ 추정**이다.
- lag가 없는 경우
  - 처치가 켜진 시점들의 평균 결과와 꺼진 시점들의 평균 결과를 직접 비교
$$\hat\tau = \bar Y_{\text{ON}} - \bar Y_{\text{OFF}}$$

- lag가 있는 경우
  - 회귀모델로 시차별 계수 $\hat\beta_l$을 추정하고, 이들의 합으로 전체 효과를 계산한다:
  - $l$: 시차(lag) 인덱스
  - $\hat\beta_l$: 시점 $t-l$의 처치가 현재 결과 $Y_t$에 미치는 효과
$$\hat\tau = \sum_{l} \hat\beta_l$$


상황설정: 한 도시 내 음식배달업체. 배달 수수료에 따른 운전기사 많아짐, 고객수요 조절효과가 배달시간에 어떤 영향을 줄까?  
(수수료 증가하면 전체 수요감소, 드라이버 상승으로 대조군에도 혜택이 갈 수 있어 복잡함)  
이런 상황에 맞는 실험 설계 방법이 스위치백 실험.  
실험대상이 1개뿐이어도 통함.
교재 예시에서는 counterfactual 효과도 다 기록해놓음. 실제로는 그룹비교 해야함.  

처치 효과가 금방 사라질 때, 여러번 처치를 반복하여 전후비교하는 방법.  
즉, **조건: 처치에 대한 lag가 작아야 한다.** ex 차수2: $Y_t = f(d_{t-2}, d_{t-1}, d_{t})$

(추가조건)
- 이 중 하나라도 불만족 시, 개체 1개로도 가능하다는 말은 성립X
- 처치 스케줄이 시간에 대해 랜덤
- carryover(lag)가 짧거나 모델링 가능
- 시스템 구조가 실험 기간 동안 안정
- 시간 블록이 충분히 많음

## 시퀀스의 잠재적 결과
lag때문에 위 식처럼 잠재적 결과를 벡터형태로 정의한다. $Y_t(\bold D) = Y_t([d_{0}, d_{1}, \ \dots, \ d_{T}])$  
여기에 두가지 가정을 덧붙여서 간소화 함:  
- Non-anticipation assumption(미래처치가 과거 결과에 영향주지 않는다)
  - 즉, t+1을 모델에 포함시키지 않겠다.
  - $Y_t(\bold D) = Y_t([d_{0}, d_{1}, \ \dots, \ d_{t}])$
  - 이월기간 크기가 m이라 가정하면: $Y_t(\bold D) = Y_t([d_{t-m}, d_{t-m+1}, \ \dots, \ d_{t}])$

m-기간 누적 처치효과:  
$$\tau_m = E\left[ Y_t(1_{t-m}, 1_{t-m+1}, \ \dots, \ 1_{t}) -Y_t(0_{t-m}, 0_{t-m+1}, \ \dots, \ 0_{t}) \right]$$

- 항상 처치를 받지 않는 상태에서 항상 받는 상태로 바뀔때의 효과임.

### 차수 추정
$Y_t = f(d_{t-2}, d_{t-1}, d_{t})$ 같은 경우에, 시차 효과가 아래 4가지 가정을 만족하면,
  - 선형성
  - 가산성(additivity)
  - 시차 간 상호작용 없음
  - 효과 크기가 시차별로 동일하거나 독립

$Y_t = f(d_{t-2}, d_{t-1}, d_{t}) = \alpha + d_{t-2} + d_{t-1} + d_{t} +e_t$라는 회귀식으로 바꿀 수 있다.  
$$\tau_m = \sum^{lags}_{l=0}\hat d_{t-l} $$
- 왠진 모르겠지만, 회귀모델에서 전체효과를 추정할 때, 이월효과의 차수 m을 정확히는 몰라도 된다고 함
- 실제 m보다 많은 시차가 포함되어있으면 위 식이 된다고 함
- 이 방법의 가정: 잠재적 결과 $Y_t(\bold D)$ 모델 설정이 정확해야한다
  - 이 방법은 모델 기반(model-based) 인과추론이며, 잠재적 결과의 동학 구조를 잘못 설정하면 랜덤화가 있어도 전체효과 추정이 깨진다.

### 디자인 기반 추정
- 관측된 결과를 '그 처치 패턴이 나올 확률의 역수'로 가중치 주는 방식으로 **잠재적 결과의 평균을 설계만으로 재구성** 한다고 해서 디자인 기반 추정이라 한다. (즉 OLS같은 모델을 안쓰니까.)
- 모델을 안쓰므로, 모델에 필요한 선형성, 가산성, covariate 끼리 독립 이런 가정이 필요없다.

(예전에 나왔던 디자인 기반 추정은 회귀분석말고 IPW사용하는 방법이었음)  
처치가 어떻게 배정되었는지 알면, 적용 가능한 IPW(역확률 가중치)같은 방법으로 $\tau_m$추정이 가능하다  
  - 처치 배정방식은 실험 설계하는 회사가 통제하므로 충족되기 쉬운 가정임.
  - 처치확률의 역수: $$E[\hat Y_d]=N^{-1}\Sigma(Y_d\bold1(D=d)/P(D=d))$$를 곱해 잠재적 결과를 재구성한다. (이 식은 예전에 본 propensity score 식)
    - 잠재적 결과가 처치벡터로 정의되어 있으므로, lag길이만큼 동일한 처치가 나올 확률인 $P(\bold D_{t-m:t}=\bold d)$를 계산하면 된다.
      - D: 현재 및 최근m개 처치 벡터
      - d: 상수 처치 d 벡터
  - $$\hat Y({\bold d})=\frac1{T-m}\sum_{t=m+1}^T Y_t\frac{\bold{1(D_{t-m:t}=d)}}{P\bold{(D_{t-m:t}=d)}}$$
    - 최근m개 처치와 현재 처치가 동일할 때마다 관측된 결과를 실행확률로 곱해주고, 곱해진 결과의 평균을 구함
  - 최종 IPW추정량: 
    $$
    \hat\tau
    =
    \frac{1}{T-m}
    \sum_{t=m+1}^{T}
    \left[
    \frac{Y_t\,\mathbf{1(D_{t-m:t}=1)}}{P\mathbf{(D_{t-m:t}=1)}}
    -
    \frac{Y_t\,\mathbf{1(D_{t-m:t}=0)}}{P\mathbf{(D_{t-m:t}=0)}}
    \right]
    $$
    * 각 시점 $t$에서
      * lag-window $(t-m)$~$t$ 구간의 처치 패턴을 보고
      * "1 패턴"이 발생한 경우에는 $1/P(D=1)$ 로 보정
      * "0 패턴"이 발생한 경우에는 $1/P(D=0)$ 로 보정
      * 이후 두 잠재적 결과 평균의 차이를 구하는 구조다.
 - 이 식을 활용해서 500여개 스위치백 실험을 시뮬레이션 돌리면 됨.

## 스위치백 실험에서 IPW, OLS 선택 기준
### 가정 수준 비교
| 구분               | IPW            | OLS |
| ---------------- | -------------- | --- |
| 랜덤화              | 필요             | 필요  |
| 처치 확률            | 필요 (정확히 알아야 함) | 불필요 |
| Non-anticipation | 필요             | 필요  |
| finite lag       | 필요             | 필요  |
| 선형성              | ❌              | ⭕   |
| 가산성              | ❌              | ⭕   |
| 시차 상호작용 없음       | ❌              | ⭕   |
* **IPW**: “랜덤화만 믿는다”
* **OLS**: “랜덤화 + 구조를 믿는다”

### 분산–편향 관점의 차이
#### IPW
* **불편성(unbiased)** 강함
* 분산이 큼
* 특히 (P(D_{t-m:t}=d))가 작으면
  * 가중치 폭발
  * 추정 불안정
#### OLS
* 분산이 훨씬 작음
* 하지만:
  * 모델이 틀리면 **bias 발생**
  * 랜덤화가 있어도 보호되지 않음

### 실무에서의 권장 사용법
1. **IPW로 1차 추정**
   * 최소 가정
   * 설계가 제대로 작동했는지 확인
2. **OLS로 효율 개선**
   * 분산 감소
   * 결과 안정성 확인
3. **두 결과를 비교**
   * 크게 다르면 → 모델 가정 의심
   * 비슷하면 → OLS 결과 채택 가능

### 언제 무엇을 써야 하나 (요약 표)
| 상황         | 추천                |
| ---------- | ----------------- |
| 설계 신뢰도만 강조 | IPW               |
| 표본 수 적음    | OLS (단, 가정 점검 필수) |
| lag 구조 불확실 | IPW               |
| 도메인 지식 강함  | OLS               |
| 의사결정 리스크 큼 | IPW → OLS 병행      |
